# 法言天地 · AI 开放修仙游戏

中文生成式修仙文字沙盒。玩家用自然语言行动，AI 主持人生成剧情，规则引擎维护角色、背包、任务、时间与结局。本轮源码版本：**1.2.0**。

## 运行

需要 Node.js 20.6 或以上；本轮实测 Node.js 26.3.0 / npm 11.16.0。应用使用 Node 内置模块，无需安装运行依赖。

**最短路径**：双击桌面的「法言天地」快捷方式，它会调用本目录的 `启动游戏.cmd` 起服务并打开浏览器。

手动启动：

```powershell
cd D:\发言天地工作区\xianxia-game
启动游戏.cmd
# 或直接用 Node
& "C:\Users\fym10\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe" server.mjs
```

打开 <http://localhost:3000/>，填写模型接口、自己的 API Key 并选择模型，再开始游戏。Windows 下使用 `npm.cmd`，可避开 PowerShell 对 `npm.ps1` 的执行策略限制。

> 桌面旧图标 `法言天地.exe` 是 v1.1.x 的 EXE 构建，已移到 `publish\法言天地-v1.1.3.exe` 备份；不要再用它启动。

- 后端调用 `Base URL + /chat/completions`。前端目前提供四个 DeepSeek 模型选项；其他兼容服务需要相应调整模型选项。
- 慢节奏使用“叙事 → 状态提取”两段式；快节奏优先一次返回叙事和状态，失败时退回两段式。
- 存档和模型配置保存在浏览器 localStorage。Key 未加密；后端转发时不写入磁盘。仅在可信本机环境使用。
- “导出日志”调用 `/api/export-log`，默认写桌面；启动前设置 `EXPORT_DIR` 可改导出目录。
- 打包版 `法言天地.exe` 停留在 v1.1.x（已移到 `publish\法言天地-v1.1.3.exe`），不能当作 1.3.2；本轮交付的是 Node.js 源码运行版 + `启动游戏.cmd` 启动器。

## 1.7.0 境界推进按小说的节奏

- 大境界不再"攒满修为就能破"：每个大境界有**最少在境年限**——凡人 3 年、炼气 8 年、筑基 60 年、金丹 100 年、元婴 200 年、化神 300 年、炼虚 400 年、合体 500 年、大乘 700 年。
- 依据：第 176 章"潜修一二十年……再苦修百余年，就是进入结丹期也不是没可能"；第 459 章乱星海"百余年"才出一个有望元婴的结丹；第 1862 章韩立到灵界"骨龄才刚二千余岁"已至合体/大乘。
- **小境界不受限**（初期→中期→后期当年就能连破）；**大境界年限不足时引擎直接拒绝**：叙事保留、境界不动，并在诊断里记一条 `breakthrough_too_soon`。
- 每回合提示词给出"你在本境已历约 X 年，还差约 Y 年"，并允许叙事用"又是数十年过去"自然推进时间。
- 突破成功后自动记录"入本境日期"，重新计时；旧档没有记录时不拦，突破后开始计。

## 1.6.0 关系分明暗：档案只写主角知道的

- 每条人物关系都带 `known`：**亲缘/师承/同门/道侣/结义默认公开**，**仇怨/交易/主仆默认埋着**；生成时可显式 `known: true/false` 覆盖。
- 档案（图鉴 tooltip）与每回合快照**只放主角知道的**；埋着的关系不出现在玩家能看到的任何地方。
- 给 GM 另开一栏【暗中的关系·不得点破】：只允许通过神色、避讳、同行、账目、口误暗示，**不得直接说出**。
- 玩家查到实证后，提取器用 `linkReveals: [{a,b,type}]` 登记，系统**只公开这一条**，其余继续藏着。
- 旧档没有明暗标记的关系按"公开"处理，不会突然从档案里消失。

## 1.5.0 别人也有各自的关系网

- 新增 `world.npcLinks`：NPC 之间也能有**师承 / 同门 / 亲属 / 道侣 / 结义 / 主仆 / 仇怨 / 交易**八种边。
- 生成契约：`newNpcs` 每项可带 `links: [{to, type, note}]`，指向同一批或已有的人物；`family` 声明的血缘会自动成边，不用重复写。
- 提示词每回合带一段【人物关系网】（最多 8 条），要求 GM 让这些人**帮亲、护短、迁怒、通风报信**，且不得改写已登记的关系。
- **牵一发动全身**：新人的初始态度会受关系网中人影响——若其结义兄弟是你的仇人（怨≥60），他一上来就少信你 10、多记你 20 怨；反之若其同门是你信得过的人，他会先信你三分。
- 边数上限 60，存档快照里带最近 12 条；旧档没有这层照常运行。
- 图鉴里 NPC 的性格提示可以悬停看到他的关系网。

## 1.4.0 人物关系四维账本

- NPC 关系从"一个标签"升级成**四维账本**：恩（debt）、怨（grudge）、信（trust）、需（need），各 0~100。标签（道侣/师徒/结义/结仇）只是某一刻的快照。
- **修炼加成按"信"和"需"算**，不再按标签：道侣约 ×1.235、师徒 ×1.16、挚友 ×1.175；叠加封顶 ×1.3。怨 ≥60 的人（结仇/仇敌）不再给任何加成——名分再亲，有仇就不助你修行。
- 提取器 `npcRelations` 可给四维增减量：救命赠礼→恩正，伤害背信→怨正/信负，守诺患难→信正，长期需要→需正；只给标签时按标签给种子。
- **关系会折旧**：三个月没往来，信 −2、需 −3（每月结算一次）。换地图、闭关久了，旧关系自然淡——原著里"淡化"才是常态。
- 旧档没有账本的 NPC，按标签推算种子，读档不改存档、不判罚。
- 图鉴里鼠标悬停关系标签，可看四维数值。

## 1.3.2 底细要等玩家查出来

- 势力不再一开局就带"表里不一"标记：真相与线索留在 `world.js`，切片里不出现任何字样。
- 玩家用「打听 / 查探 / 跟踪 / 试探」这类动作点到某家势力，才把线索交给 GM（`noteInvestigation`），切片显示"有蹊跷"，但仍不点破。
- 叙事里查出**实证**后，提取器用 `reveals: [{faction:"白鹿观"}]` 上报，系统才标记"表里不一"、记一笔"查出底细"事迹、在图鉴打上"底细已明"，并把这家的真相写进切片。
- 没起疑就报"查明"一律不收：先有线索，才有结论。
- 本轮两条底细：白鹿观（血刀寨暗桩）、青芜王朝（向拾云门纳贡）。

## 1.3.1 随机登场，不必全部上场

- 开局不再把一地的势力全写进世界：**当家人必在**（你落脚就绕不开），另外只随机抽 1~2 家；没登场的势力仍在世界表里，等剧情走到再露面。
- 世界切片只列**已打过交道的**势力，其余只报个数（"此外还有 2 家势力未与之打过交道"），不再把名单摊开。
- 性格建议从"排队轮完 44 个"改成**随机抽样**：没遇到的人就不该出现，随机即可。

## 1.3.0 的人物性格

- 新增 `public/personality.js`：**六轴坐标**（温度 / 城府 / 守序 / 义利 / 胆气 / 情绪）× **44 个特质**，每个特质都带"一句话设定"和"说话习惯"。
- NPC 生成契约变严：除气质与真实性格外，还要给 `trait`（库内特质标签）、`desire`（想要什么）、`taboo`（碰不得什么）、`speech`（说话习惯）。欲望与忌讳是玩家可以借力的软肋与逆鳞。
- **反重复**：世界记录最近 20 位登场者的性格坐标；每回合把最近 6 位点名给模型，同一极连续出现 3 次以上就要求换面；轮换建议只从没出现过的特质里取，游标推进保证 44 个会轮完。
- 明确禁止默认写成"清冷寡言 / 傲娇 / 面冷心热"；相邻 NPC 至少要有两条轴一正一反。
- 图鉴深交后显示特质标签，悬停可见欲望、忌讳与口吻。
- 旧档无需迁移：没有新字段时按自由文本显示，行为不变。

## 1.2.0 的世界骨架

- 新增 `public/world.js`：五个凡界区域（青芜国、落霞坊、大衍王朝、赤沙荒原、寒渊海）、十二个本地势力、十一组关系，含**暗桩**设定（白鹿观实为血刀寨暗桩）。
- 开局不再由模型现编世界：区域、本地势力、路程、物价系数都来自这张表；模型仍负责人物、剧情与机遇。
- 每回合只注入一段 **≤300 字的世界切片**（当前区域、势力、可达地点与天数、物价系数、产出上限），不把整张表塞进上下文。
- **行路按表结算**：玩家抵达另一区域时，提取器填 `travelTo`，系统按路程表覆盖本回合耗时（青芜→落霞 3 日 = 0.1 月），模型不能再凭空写“赶了三日”。
- **物价有系数**：区域×大势算出的倍率随切片给出，同一颗丹在黑市就是比坊市贵。
- 高境界回到安全区会收到“此地已压不住你”的提示，收益随之递减。
- 旧档读入时幂等补一个区域坐标（优先按起始地名匹配），不改数值、不判罚；回退档同样处理。
- 状态栏显示“境界 · 当前区域”。

世界框架的抽取过程与原著依据在 `../world-framework/`（独立目录，不参与游戏运行）。

## 1.1.3 的状态输入防护

- 模型只提出更新，规则层统一检查后再应用；时间推进和大势处理也只消费同一份校验结果。
- 玩家属性只接受合法增减量，不接受直接 `set`。检查字段类型、有限数值及倍率/加法后的安全范围，非法字段不污染存档，合法独立内容继续生效。
- 普通剧情标记只接受布尔值；代码保留标记不能被伪造。物品和退款必须给出合法明确数量。
- 已完成、失败、放弃的任务不能被模型重开或改写；重复同一终态不新增事迹。同批完成/失败冲突按任务拒绝。
- 非法根输出不结算回合或日期；拦截时显示系统说明，实际面板和存档优先于叙事。突破提示依据真实境界变化。
- 问题诊断最多保留 30 次、每次 10 项，只记录静态诊断，不保存原始状态提案。完整对话日志仍包含正常对话，请勿在对话中粘贴密钥。

这不是完全消除幻觉：奖励是否合理、物品是否真有来源、突破是否满足全部条件，仍待后续规则化。

本轮免 Key 试玩：

```powershell
npm.cmd run review:guards
```

打开 <http://127.0.0.1:3103/__review>，选快/慢节奏并继续游戏，依次输入 `混合校验`、`终态改写`、`冲突更新`、`根数组`、`数值溢出`、`正常增减`、`特殊名称`。审阅端口与正式存档隔离，固定响应不访问真实模型。“导出日志”在模拟服务下回退为浏览器下载，不写桌面。

## 1.1.2 的任务期限

- 沿用每月 30 天、每年 12 月；三日期限按游戏日期计算，不再使用三回合。
- 同日短对话不消耗期限；截止当天仍有效，次日才超时。
- 本回合完成任务优先于本回合结束时的超时检查。
- 旅途末新接的任务，从抵达后的日期开始计算相对期限。
- 已确认截止日期和原期限条款保持固定，重复提取不能续期或提前。本版本不支持已确认期限自动改期。
- 旧存档保留任务内容和状态。无法还原日期的旧回合期限显示“旧期限待确认”，不猜测“一回合一天”；剧情给出明确新期限后补录。

## 本地审阅，不消耗模型额度

```powershell
npm.cmd run review:deadlines
```

打开 <http://127.0.0.1:3100/__review>，选择三日期限或旧档场景，点“继续上次游戏”，再打开右侧“任务”页。

真实前端搭配固定模拟响应，只监听本机地址，不转发任何外部 API 请求。3100 端口测试存档与 localhost:3000 的正式存档隔离。

| 输入动作 | 预期 |
| --- | --- |
| `聊一聊` | 同日对话，剩余天数不变 |
| `过三天` | 到截止日，仍有效 |
| 再输入 `过一天` | 超时，提示截止日期和当前日期 |
| 重载场景后输入 `完成并过四天` | 已完成，不被超时覆盖 |
| 旧档场景输入 `补录期限` | 待确认任务获得明确截止日期 |
| `旅途接取` | 一月旅行末接任务，新任务仍有完整三天 |

## 测试

```powershell
npm.cmd test
node --check public/game.js
node --check public/app.js
node --check server.mjs
```

默认运行 16 套离线测试：基础规则、大势时间轴、防幻觉、长期记忆、NPC 性格、死亡规则、任务日期、状态输入与任务终态、世界骨架、人物性格多元、势力底细揭露、审阅白名单、人物关系四维账本、人物关系网、关系明暗、境界节奏。测试子进程禁用 `fetch`，不会调用付费模型。

根目录其他 `test_*.mjs` 中有许多在线联调脚本，不要批量运行。Key 请通过脚本约定的环境变量传入，不使用命令行参数。

可选无界面前端集成检查（需要本地 Playwright；先启动审阅服务）：

```powershell
node scripts/check-deadlines-browser.mjs
# 状态防护检查需先启动 review:guards
node scripts/check-state-guards-browser.mjs
node scripts/check-server.mjs
```

脚本新建临时浏览器上下文，不连接个人浏览器，只允许请求审阅端口。可用 `PLAYWRIGHT_MODULE` 指向已安装的包，用 `REVIEW_BROWSER_EXECUTABLE` 指向本地浏览器引擎。截图输出到 `docs/reviews/`。

## 开发结构与协作

| 文件 | 职责 |
| --- | --- |
| `public/game.js` | 规则、日期、任务、结局、状态合并、GM/提取器提示词 |
| `public/world.js` | 世界骨架：区域、势力、关系、路程、物价系数、每回合切片 |
| `public/personality.js` | 人物性格：六轴坐标、44 个特质、反重复与轮换建议 |
| `public/app.js` | 对话循环、存档、任务界面、通知、日志 |
| `public/index.html` / `style.css` | 页面与样式 |
| `server.mjs` / `server.cjs` | 静态托管、模型转发、日志导出、SEA 支持 |
| `tests/` | 离线测试入口、日期回归、脱敏旧任务夹具 |
| `scripts/` | 模拟审阅和可选无界面集成检查 |
| `build-exe.ps1` / `publish/` | EXE 构建与发布脚本，本轮未重新打包 |

协作规则见 [AGENTS.md](AGENTS.md)。同一文件同一时刻只分配一个修改负责人；规则在 game.js 中实现，界面不另写到期算法。

第一轮设计见 [日期设计记录](docs/superpowers/specs/2026-10-21-calendar-deadlines-design.md)，结果见 [第一轮交付报告](docs/reviews/2026-10-21-delivery.md)。第二轮接口与范围见 [状态防护设计](docs/superpowers/specs/2026-10-21-state-input-guards-design.md)，结果见 [第二轮交付报告](docs/reviews/2026-10-21-state-guards-delivery.md)。
