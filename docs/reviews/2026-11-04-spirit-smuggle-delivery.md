## 规则

1. **节点**：`SPACE_NODES` 三处——无边海·断界崖（30%）、天罗国·无光谷（22%）、奇渊岛·沉星渊（35%）。走到那里，世界切片多一行【异象】，提示界力薄。
2. **门槛**：`SMUGGLE_MIN = 元婴后期`；不够就回"修为不足，会被空间之力化为乌有"。
3. **成功率** `smuggleChance = 节点稳定性 + (有化界珠 ? 0.3 : 0) + (境界超出元婴后期 × 0.05)`，夹在 3%~90%。
4. **结果三档**：
   - 成功 → 随机落在风元大陆/雷海/血天大陆，`flags.spiritOutlaw = true`（无仙籍），天渊卫与接引堂转为敌对，化界珠/万年灵液/破界符折在通道里。
   - 失败 → 60% 身死道消（`hp = 0`、`deathByRisk`），40% 重伤被甩回原地（气血降到一成、寿元 −20 年）。
5. **与正途并存**：化神后期 + 修为圆满，仍可正常破界、落飞灵台、登记在册；两条路的区别只有一个——**有没有仙籍**。

## 接口

```js
SPACE_NODES / nodeInRegion(regionId)      // world.js
SMUGGLE_MIN = '元婴后期'
smuggleChance(player, world, node)
attemptSmuggle(player, world, rand) -> { ok, note, death? }
hasItemNamed(world, key)
```

模型侧新增字段 `smuggle: { node }`（两套 schema 与提示词同步），引擎掷骰，叙事不得自编结果。

## 踩坑

- 切片加了【异象】一行之后，`chisha`（天罗国，有节点）的切片从 ~380 字涨到 **404 字**，老的"切片不超过 400 字"断言当场红。把提示压成一句短的，长度回到限内。
- 测试里两次 `Math.random` 的调用顺序（先判成败、再判生死）一开始写反了，导致"必死"用例拿到的是"重伤"分支。改成显式序列掷点。
