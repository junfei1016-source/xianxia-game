# 第八轮交付：关系分明暗，档案只写主角知道的（v1.6.0）

日期：2026-11-02 ｜ 范围：把人物关系网拆成"明面"与"埋藏"

## 问题

上一轮把 NPC 之间的关系全塞进提示词，问题有两个：

1. **档案会剧透**：苏瑶与血刀寨有仇这种事，玩家还没查到，图鉴就先写着；
2. **模型会说漏**：关系直接摆在每回合的【人物关系网】里，GM 很容易顺口讲出来。

## 做法：一条关系带 `known`

```
{ a: '苏瑶', b: '血刀寨', type: '仇怨', note: '夺货之恨', known: false }
```

### 默认明暗

| 关系 | 默认 |
| --- | --- |
| 亲属、师承、同门、道侣、结义 | 公开 |
| 仇怨、交易、主仆 | 埋着 |

生成时可以显式写 `known: true/false` 覆盖——当众结拜、私下达成的交易，都由模型决定。
`family` 自动成边固定为公开（亲属藏不住）。

### 三处只放"主角知道的"

| 位置 | 明关系 | 暗关系 |
| --- | --- | --- |
| 图鉴 tooltip | ✅ 显示 | ❌ 不显示 |
| 每回合快照 `context.npcLinks` | ✅ 带 12 条 | ❌ 不带 |
| 提示词 | 进【人物关系网】 | 进【暗中的关系·不得点破】 |

暗关系仍交给 GM，是因为**不交会前后矛盾**（它自己写的边，隔几回合就忘）。但口径锁死：

> 这些关系玩家尚不知道：你只能通过细节暗示（神色、避讳、同行、账目、口误），不得直接说出，
> 也不得让玩家凭空知道；玩家查明实证后，用 linkReveals 登记。

### 揭露

提取器新增 `linkReveals: [{a, b, type?}]`。系统只把**被查到的这一条**改成 `known: true`，
写一笔「查出关系」事迹，并回一句【关系浮出水面】给玩家；其余暗关系不动。

写测试时踩到一个真问题：schema 里 `links` 一开始没放 `known` 字段，显式覆盖被当成"未知字段"丢掉了——
**默认值能过，显式覆盖过不了**，正好被"显式覆盖"那条测试抓住。

## 遗留

- 暗关系目前只能靠 GM 主动 `linkReveals`；玩家"打听某人"这个动作不会自动推进揭露（势力底细有 `noteInvestigation`，人物关系还没有对应的调查钩子）。
- 没有"半公开"状态（起疑但未证实），只有 known 的真/假。
- 暗关系也不参与态度传导：新人与暗关系网中人的连带影响目前只按明关系算。
- 档案里没有"关系图"，只有文字 tooltip。
