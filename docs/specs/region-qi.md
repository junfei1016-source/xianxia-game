# 地脉枯荣：灵气只会被采枯，封山才回补（v1.37.1）

日期：2026-11-04。基线 v1.36.0（灵根补全），本文件取代作废的 `region-drift.md`。

## 为什么改（v1.37.0 错在哪）

v1.37.0 做的是"灵气每半年随机涨落 ±1"，引文写的是「第 220 章：灵脉有枯竭之日」。**逐字核对原文后，这句是引反的**——第 220 章原话是：

> 这些灵脉一旦成形，便会自动散发出淡淡的灵气，让当地的灵气循环不绝，**不会有枯竭之日**。

同一章还写：天地灵气"有的地方浓郁一些，有的地方淡薄一点"，灵气浓重之地会形成灵脉，灵脉中灵气郁结最浓处称"灵眼"，"当然最适合修仙者打坐修炼了"。

真正支持"会枯"的是第 172 章《选择》：

> 因为禁地频繁的开启，会让其内的灵气大量流失，灵药的产生和生长的速度都会减缓起来。这种临时的封闭举措，将会重新改变灵气的密度，让其再次恢复到正常的水准。
> ……若想真正恢复禁地内灵药的正常数量，必须把圈封的时间拖延到足足千年之久才行。

⇒ 原著口径是：**灵脉自循环不枯；枯是采出来的，恢复靠封山，且恢复远慢于流失。**

同时作废的两处引文：v1.37.0 还引了"第 358、363 章：修士越来越多，灵石越采越少"——查证后这两章分别是"无边海、慕兰人"与"传送"，与灵气枯荣无关，属误引，已删除。

## 规则

1. **加压**：每次成功采集给该区域加压力，按稀有度——凡品 4、灵品 8、玄品 14、仙品 22、神品 30。
2. **自消**：不采的月份压力每月 −2。
3. **掉档**：压力 ≥ 30 时扣掉 30，灵气降一寸（最低 1）；一刻钟内连采多次会连掉。
4. **回补**：灵气低于底值、压力为 0、且连续 24 个月无人采，回升一寸；上限**永远是表里的底值**（灵脉只回常态，不会变更好）。回补过一次重新计时。
5. **影响**：灵气决定修炼倍率（`qiCultMult`：以 3 为基准，每高一寸 +0.05，被压到最低时不低于 0.70）；决定采集点上限（`regionNodeCap` 用实际灵气）；决定本地物价（只乘"枯荣差"，没被采过的区域价格与旧口径完全一致）。
6. **可见**：掉档与回补都写「地脉纪事」（最多 12 条），当回合弹一行系统提示；世界切片带当前灵气档位 + 本地最近两条纪事。
7. **兼容**：旧档由 `ensureRegionQi` 幂等补空；读档只补字段，不补枯荣、不判罚；静态九域表永不被改写。

## 接口

数据层 `public/world.js`：

```js
QI_LABELS                                   // 1..6 → 枯涸/稀薄/寻常/丰沛/浓郁/灵涌
REGION_QI_RULES = { harvestCost, pressurePerLevel: 30, idleDecayPerMonth: 2, recoverPerMonths: 24, maxChronicle: 12 }
regionQi(region, world)     // 当前灵气：存档值 clamp 到 [1, 底值]
regionQiState(world, id)    // { qi, pressure, idle }
qiLabel(qi) / qiCultMult(qi) / qiPriceMult(qi)
```

规则层 `public/game.js`：

```js
ensureRegionQi(world)                  // 幂等补字段：regionQi / regionQiLog / qiDays / qiMonths
noteRegionHarvest(world, region, rarity) // 采一次加压（gatherMaterials 内调用）
evolveRegionQi(world, months)          // 按月推进：自消、掉档、回补；返回纪事文本
regionCultMult(world)                  // 所在地上灵气对修炼的倍率
```
