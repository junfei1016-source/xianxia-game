# 区域生成标准（玩家开辟新域）

> 适用：玩家在游戏里**开辟、发现、打通**一片新地界时。
> 模型只能"提议"，能否入图由 `public/world.js` 的 `validateRegionProposal` 判定。
> 静态九域不可改；新域存进存档（`world.dynamicRegions`），可跨回合、可读档。

## 一、必填字段

| 字段 | 规则 |
| --- | --- |
| `name` | 区域名，**2~8 字**，不得与已有区域重名 |
| `terrain` | 地形，2~8 字（如"泽国水乡""陨坑荒原"） |
| `qi` | 灵气，**1~6 的整数** |
| `danger` | 危险，**1~5 的整数** |
| `products` | 产出品阶数组，取值仅限 凡品/灵品/玄品/仙品/神品，至少一项 |
| `links` | `[{to: 已存在区域名, days: 单程日数}]`，**至少一条**，天数 1~60 的整数 |
| `desc` | 简述，**≤90 字** |

## 二、平衡约束（防止模型给玩家开挂）

1. **产出上限 = floor((灵气 + 危险) / 2)**：
   - 灵气 2·危险 1 → 最多灵品；
   - 灵气 3·危险 3 → 最多玄品；
   - 灵气 3·危险 5 → 最多仙品。
2. **仙品以上**：灵气 ≥4 **或** 危险 ≥4（不能又安全又出仙材）。
3. **神品**：灵气 ≥5。
4. **必须有路**：没有通路的地界进不了图（避免"凭空多一块秘境"）。
5. **路程对称**：系统会把返程按同样天数补上，`travelDays` 双向一致。
6. **数量上限**：一局最多开辟 **24** 块新域。

## 三、系统自动补的字段

| 字段 | 规则 |
| --- | --- |
| `id` | 由名字生成（非 ASCII 时用 `dyn_N`），保证唯一 |
| `price` | 由灵气/危险推算：`1 + (qi-2)×0.1 + (danger-2)×0.1`，夹在 0.7~3.0 |
| `dynamic` | 恒为 `true`，便于辨认 |

## 四、被拒绝时会发生什么

- 提案**整条丢弃**，世界不脏（不会留下半块区域）；
- 诊断里记一条 `region_invalid`，附具体原因（如"灵气7 越界""出不了仙品""没有通路"）；
- 叙事照常保留——玩家可以"走到了雾里却什么也没找到"，但不能凭空获得地界与产出。

## 五、示例

合法：

```json
{
  "name": "雾隐泽",
  "terrain": "泽国水乡",
  "qi": 3,
  "danger": 3,
  "products": ["灵品", "玄品"],
  "links": [{ "to": "青芜国", "days": 5 }],
  "desc": "终年大雾的泽国，散修在此避祸。"
}
```

不合法（会被拒）：

```json
{ "name": "仙府", "terrain": "云海", "qi": 9, "danger": 9, "products": ["神品"], "links": [] }
```

三处都违规：灵气/危险越界、无通路；即便灵气合格，灵气 9 也不可能存在。

## 六、留给后续

- 新域还不能自带势力与地标（目前只有区域本身）；
- 新域不参与拍卖会排期（等拍卖改成"按区域随机"后再接）；
- 没有"区域演化"：新域不会随大势变危险或衰竭。
