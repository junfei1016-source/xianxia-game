## 三、逐轮要点

### v1.2.0 世界骨架接入（4a41b94）

- 新增 `public/world.js`：区域 / 势力 / 势力关系 / 物价系数 / 路程表，代码算距离与价格，模型不再自造。

- 测试：世界骨架 16 条（对称性、连通、物价带、切片长度）。

### v1.3.0 人物性格多元化（7e91412）

- 新增 `public/personality.js`：六轴（温度/城府/守序/义利/胆气/情绪）+ 44 条特质，每条带 gist 与口吻。

### v1.7.0 境界推进按小说节奏（b8e47c7）

- 依据：第 176 章「再苦修百余年才可能结丹」、第 459 章「百余年一个元婴苗子」、第 1862 章韩立「骨龄才刚二千余岁」。
- `REALM_MIN_YEARS`：凡人 3 / 炼气 8 / 筑基 60 / 金丹 100 / 元婴 200 / 化神 300 / 炼虚 400 / 合体 500 / 大乘 700。
- 小境界不受限；大境界年限不足时引擎拒绝，叙事保留、境界不动，记 `breakthrough_too_soon`。

### v1.8.0 闭关成为主推进手段（bbd6701）

- 闭关修为不再由模型报数：`每月 = 100 ÷ (最少在境年限 × 12)`，模型给的 `delta` 降级为效率提示（0.5~2 倍）。
- 筑基闭关十年 ≈ 16.7%，六十年圆满；凡人三年圆满。
- 连续闭关递减保留（1 / 0.85 / 0.7 / 0.6）。
- 测试：闭关结算 9 条；旧断言「首次闭关满额 10 点」按新契约改为约 2.78。

### v1.9.0 闭关会被打断（4f23929）

- 闭关前掷一次：仇家 / 敌对势力 / 心魔 / 不速之客。
- 概率 = 8% + 危险度×2% + 乱世 5% + 敌对势力×5%（≤15%）+ 结仇人数×3%（≤9%）+ 走火入魔 10%，封顶 60%。
- 掷中先定「第 1~3 年、谁上门」，写进指引逼 GM 写「提前出关」，结算压时长，记「闭关受扰」。
- 测试：闭关打断 10 条。

### v1.10.0 护法（d822b4f）

### v1.18.0 区域生成标准（8b5727e）

- 玩家开辟新域时模型只能提议 `newRegion`，由 `validateRegionProposal` 判定。
- 标准：名字 2~8 字不重名、灵气 1~6、危险 1~5、至少一条 1~60 日通路、描述 ≤90 字。
- 产出上限 = `floor((灵气+危险)/2)`；仙品要灵气或危险 ≥4；神品要灵气 ≥5。
- 合格 → `world.dynamicRegions`，返程自动补齐（对称），切片/物价/行路都认；不合格整条丢弃并记 `region_invalid`。
- 新增 `docs/specs/region-generation-standard.md`；测试 13 条。

## 五、工程教训

1. **`node --test` 在沙箱里起子进程会 EPERM**：改为直接 `node tests/xxx.test.mjs`，`run-offline.mjs` 用 `spawnSync` 逐个跑。
2. **每个新模块都要进审阅白名单**：`world.js`/`personality.js`/`pills.js` 三次踩到，`review-assets` 测试现在守着。
3. **版本号要两处同步**：`GAME_VERSION` 与 `package.json` 曾差八个版本，`version-sync` 测试兜底。
4. **中文变量名必须与关键字隔开**：`const 残缺` 被解析成 `const残缺`。
5. **契约变化会让旧测试红**，要判断是「代码错」还是「测试按旧契约写」：闭关满额、拍卖日期、突破结算各遇到一次。
6. **引擎要当裁判、模型只提案**：修为、药效、价格、区域，全部由代码结算，模型写的数值被忽略或按条拒绝。
7. **世界表按「自洽」写测试**，不要写死数量——地图从 5 域扩到 9 域时，16 条旧测试零改动通过。
