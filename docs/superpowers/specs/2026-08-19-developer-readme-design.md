# 《法言天地》开发者向 README 设计说明

## 背景

现有 `README.md` 能说明项目定位和基本启动方式，但已经落后于当前实现：测试数量、快慢节奏调用链、结局、物品与关系系统、日志导出等描述不准确或不完整。新 README 将以接手和维护项目的开发者为主要读者，同时保留简短的玩家运行说明。

## 目标

- 让新开发者在十分钟内理解项目边界、启动方式、主要模块和回合数据流。
- 准确说明模型协议、快慢节奏调用链、重试与降级行为。
- 提供可直接执行的开发、测试、真实模型联调和 Windows SEA 打包命令。
- 明确 API Key、日志、本地服务监听和模型费用的安全边界。
- 公开记录已确认的实现缺陷与技术债，避免把缺陷描述成已完成能力。
- 删除过时或无法保证的宣传性表述。

## 非目标

- 不把 README 写成全部境界、词条和数值的完整规则百科。
- 不修改游戏源码、规则或页面行为。
- 不承诺所有 OpenAI 兼容服务均可直接使用。
- 不为当前 README 制作或生成新的游戏截图；架构关系使用 Mermaid 图表达。

## 架构与数据流设计

README 使用一张 Mermaid 流程图表达以下边界：

- `public/index.html` 提供单页页面结构。
- `public/app.js` 负责模型调用、回合编排、UI 渲染、存档、重试和降级。
- `public/game.js` 负责规则、提示词、状态合并、时间、战斗、任务、成就和结局。
- 浏览器 `localStorage` 保存模型配置、自动档和三个手动档。
- `server.mjs` 提供静态托管、`/api/chat` 模型代理和 `/api/export-log` 日志写出。
- 上游接口必须符合 OpenAI Chat Completions 风格的普通响应或 SSE 流式响应。

慢节奏回合描述为“流式纯叙事 -> JSON 状态提取 -> 规则结算”。快节奏描述为“优先一次合并生成叙事和状态 -> 失败时回退两段式”。结算顺序描述为“状态更新 -> 时间、任务、成就和结局检查 -> 自动存档 -> UI 渲染”。

## 运行与配置设计

- 源码模式要求 Node.js 18 或更高版本，并说明项目没有第三方运行依赖，无需先执行 `npm install`。
- 主要命令为 `npm start`，同时给出 `node server.mjs` 和 `node server.mjs --open`。
- PowerShell 换端口使用 `$env:PORT=4000`，避免沿用 CMD 语法。
- 当前前端模型下拉框只提供四个 DeepSeek 模型；协议层兼容不等于 UI 可直接选择任意模型。
- 模型配置说明包括 Base URL、API Key、Model 和 JSON 模式。

## 安全与成本设计

- API Key 以明文保存在当前站点的浏览器 `localStorage`。
- 每次请求都会把 Key 发送到本地代理，再以 Bearer Token 转发给上游；服务端不把 Key 写入磁盘或存档。
- 本地服务当前没有身份验证，并监听所有网络接口；不得建议将端口暴露到公网或不可信局域网。
- 导出日志不含模型配置，但包含完整对话和世界状态，玩家主动输入的敏感内容仍可能进入日志。
- 慢节奏通常每回合至少两次模型调用；快节奏通常一次，失败回退会增加调用；自动演示和记忆摘要也可能产生费用。

## 游戏规则速查设计

规则章节只解释开发时需要理解的核心循环和边界：

- 核心循环为“修炼 -> 探索、任务、关系或战斗获取资源与机缘 -> 突破 -> 更高风险区域 -> 渡劫飞升”。
- 主要状态包括气血、寿元、灵石、正邪、声望、修为、装备、关系、任务和时间。
- 小境界、大境界与渡劫采用不同门槛；避免把所有突破都写成必须依赖机缘。
- 普通危险通常先进入“生死一线”，渡劫失败另有直接死亡路径。
- 只把“飞升成仙”称为主目标胜利；列出当前六种终局，并说明“一统江湖”不是飞升胜利。
- 使用短表格概括难度、节奏、回合上限、修为倍率、开局方式、篇幅和天下大势，不复制全部数值常量。

## 测试设计

README 使用测试矩阵区分：

- `npm test` / `node test.mjs`：不需要服务、Key 或网络的主离线规则测试；当前实测 139 条通过。
- `test_*.mjs` 专项脚本：按脚本用途区分离线规则与真实模型联调。
- `test_live.mjs`、`test_smoke.mjs`、`test_quest.mjs`、`test_stream.mjs`：需要已启动服务、API Key、网络和额度。
- `sea-check*.mjs`：Windows SEA 产物检查。

所有真实模型命令都使用环境变量示例，并明确不会把真实 Key 写入 README。

## 错误处理与调试设计

- 空响应、HTTP 429 和 5xx 最多重试三次；JSON 模式连续空响应后会尝试非 JSON 请求。
- 这些机制只降低失败率，不保证叙事或状态永远不丢失。
- `/api/export-log` 默认写桌面，可用 `EXPORT_DIR` 覆盖；服务端写入失败时浏览器回退到下载。
- 常见问题覆盖端口占用、Key 或余额、接口协议不兼容、JSON 模式问题和 EXE 系统警告。

## 已知问题与技术债

README 公开记录以下现状：

1. “突破大境界”按钮判定成功后不推进境界，文字叙事的 `realmChange` 路径仍可工作。
2. 创世生成的起始地点没有自动加入地点图鉴。
3. 模型生成的支线任务可能缺少期限。
4. 回合上限检查使用 `world.turn > limit`，存在一回合边界偏差。
5. UI 模型字段是四个 DeepSeek 值的下拉框，尚不能自由输入其他兼容模型名。
6. 本地服务缺少认证、限流和仅回环地址绑定，不适合作为公网服务。
