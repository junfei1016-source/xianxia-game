# 第二轮：统一状态输入校验与任务终态保护

日期：2026-10-21。基线：0730af8 / v1.1.2。目标版本：v1.1.3。

## 需求与范围

模型负责叙事和提出更新，代码负责校验与实际落地。保留自由剧情、合法 delta、旧档和第一轮的日期期限。此次不重新设计突破条件、经济奖励预算或物品来源授权；这些仍是后续风险，不能把本轮描述为完全消除幻觉。

## 已确定的玩法选择

1. 玩家数值仅允许有限、安全数值的增减（delta），兼容原有裸数字和平铺字段。模型直接 set 一律拒绝，包括外挂模式；合法 delta 仍走现有伤害、收益和外挂规则。不另加任意平衡上限。
2. 非法字段或数组条目单独拒绝，不丢弃同批合法的独立更新。根不是普通对象时整份拒绝，不进行游戏状态结算。数值在倍率和加法后再次检查，绝对值不得超过 Number.MAX_SAFE_INTEGER。
3. completed / failed / cancelled 为任务终态。只能 active→completed/failed，active 可补录缺失期限；终态不能改状态、期限或补造相反事迹。重复相同终态是安静的幂等操作。同一任务同批完成与失败冲突则该任务的更新全部拒绝。放弃只由玩家按钮触发。对应任务的精确系统事迹标签（已完成、已失败、已放弃、已失败（超时））由真实状态迁移生成，不能用 newEvents 独立伪造。
4. 普通剧情 flags 仅接受布尔值；屏蔽原型保留键和代码管理的死亡、时代到期、目标达成等标记。保留 closedDoor；deathImminent / qiDeviation 只允许 false 清除，不允许 true 伪造。撤回也不能删除保留标记。
5. 新物品与退款数量必须明确、有限，退款还必须大于 0；不再把缺失/非法数量当成 +1，也不把负退款取绝对值变成奖励。无效日期保留待确认语义，不能静默成为无期限。
6. 叙事可能先于校验显示；被拦截时必须可见说明以实际面板和存档为准。突破动画和目标成功提示仅基于真实状态差分。

## 接口合同

规则层导出 `validateStateOutput(input) => { out, issues }`。out 为已接受的普通对象，非法根为 null。issues 为静态诊断，条目形如 `{ code, path, message }`；path 只能是已知静态字段路径，不包含输入值、动态名称或未知字段名。

`applyStateUpdates(player, world, input, report = {})` 在入口调用该校验，保持原来的字符串/null 返回值（战斗/复活说明）。report.out 提供唯一的规范化提案；report.issues 包含输入校验和规则执行拒绝的诊断。界面将 report.out 或空对象传给后续时间推进与大势处理，不得再消费原始提案。

诊断代码：invalid_root、invalid_type、invalid_number、forbidden_set、unsafe_key、unknown_field、terminal_quest、conflicting_quest_updates、numeric_overflow、forbidden_flag。可按实际细化，但不得放入原始内容。

规则层在有问题时写入 world.validationLog，最多保留最近 30 次问题回合、每次最多 10 条静态诊断，含 turn 和处理结果；不保存模型原文/输入值/API Key。不改存档键，不整包替换世界或任务对象引用。

parseLLMJSON 只返回普通对象：先尝试解析完整文本，合法 JSON 根数组/标量明确拒绝，不截取数组内部对象。继续兼容代码围栏、中文弯引号及附加说明中的对象。

所有被规则层消费的结构均应校验：数值、timeMonths、gainType、risk、died、combat、realmChange、flags、NPC/地点/功法/事迹/势力/关系/机缘、物品/装备、goal、eraChange、任务、effectRequests、retract。未知更新字段移除；叙事字段允许保留安全字符串以兼容快速模式。
